# Way 产品需求文档

更新日期：2026-10-13

## 1. 产品背景与定位

自由行让旅行者自己决定去哪、玩什么、停留多久。国家广告研究院《新时代文旅品牌发展研究报告：文化赋能·体验驱动·价值引领》引用的 2026 年 Z 世代文旅消费者专项调研（样本量超过 1,000）显示，95.19% 的受访者偏好自由行，6.73% 偏好传统跟团游。这些结果反映了受访者对自主安排行程的偏好。[资料来源：研究报告](https://pdf.dfcfw.com/pdf/H3_AP202606031823205706_1.pdf)

规划一趟自由行需要比较目的地与活动、安排每天的路线、衔接交通住宿，还要考虑假期、预算和同行人的需要。Way 的产品判断是：将这些信息放在同一份可查看、可修改的计划中，有助于用户完成规划和出行准备。该判断仍需通过用户反馈和实际使用验证；上述调查支持自由行的偏好趋势，尚不能证明用户对路线与路书一体化工具的具体需求。

Way 帮用户从选择目的地、挑选体验，一直安排到每天的行程。还没想好去哪时，可以先看推荐；已经有目的地、必去地点或交通预订时，可以直接据此规划。计划生成后，还能增减地点、调整天数和游玩节奏。

Way 是一款 AI 自由行规划工具，**将地图上的路线与每天的旅行攻略放在同一份计划中。**

路线用来看全程怎么走，包括地点顺序、停留时间、交通方式和住宿区域。路书是按天整理的旅行攻略，写清当天怎么玩、建议花多久、哪些活动要预约，以及出发前需要准备什么。

路线和路书中的安排必须一致。例如，用户删掉某个徒步地点后，当天的交通、玩法和装备提醒也要随之更新。

## 2. 目标用户与使用场景

主要面向喜欢自己安排行程、会参考线上攻略或 AI 建议的年轻自由行旅客，也适用于有同样需求的其他旅客。用户不必先做好攻略，也不必一开始就确定所有信息。

| 开始时的情况 | 用户需要的帮助 | Way 应交付的结果 |
| --- | --- | --- |
| 还没决定去哪，只知道假期长度、兴趣或预算 | 找到值得考虑的目的地，理解它们的差别 | 少量有明显差异的旅行方向及选择理由 |
| 已确定国家或城市，还不知道具体怎么玩 | 了解当地有哪些活动，挑选感兴趣的内容 | 可比较、可多选的地点与体验，以及详情来源 |
| 已有必去地点或订好的交通、住宿 | 在现有条件下安排剩余行程 | 保留固定安排的每日路线，以及对应的玩法与准备事项 |
| 已有路线，希望改变天数、地点或节奏 | 看清修改会影响什么，得到更新后的安排 | 同步更新的路线与路书、主要变化和无法兼顾的事项 |
| 已形成计划，正在准备出发或旅途中查阅 | 快速找到当天安排和相关细节 | 按天查阅的地图、交通、玩法、预约提醒与备选安排 |

独自旅行、和朋友出游、带父母旅行，都可能有不同的安排。是否喜欢热闹、能否自驾、能接受多少步行，应以用户说明为准，不能只凭同行人的身份判断。

## 3. 产品目标

第一，用户能够看懂有哪些选择以及各自的利弊。例如，两个地点都适合看风景，Way 要说明景观、交通和所需时间的差别，而不只列出两个名称。

第二，用户的要求能够体现在结果中。喜欢什么、不想做什么、已订好什么，都应影响推荐和安排；无法同时满足时，明确说明冲突和可调整的办法。

第三，路线与路书能够一起用于出行准备和途中查阅。用户既能看清全程怎么走，也能找到当天怎么玩、交通怎么衔接、哪些活动需要预约，以及哪些事项仍待核实。

第四，修改后得到一份更新的计划。用户改变一个条件后，路线、路书和相关提醒一起更新，不受影响的安排保留。

对应的质量和速度目标统一列在第 7 节。

## 4. 核心使用流程

以下描述 Live 的完整规划流程。Showcase 使用预设旅行条件、资料和对话选项，供用户体验选择地点、生成路线、阅读路书及调整安排。

### 4.1 从旅行想法开始

首页允许用户自由描述需求，不要求先填完一张表。Way 先回应用户已经说明的内容，再补问影响当前选择的关键信息。

探索阶段可以暂时没有日期或目的地；需要判断往返时间、具体班次或预约条件时，再补齐相应信息。已有航班、住宿或必去活动应作为后续安排的依据。

### 4.2 挑选目的地和体验

需要推荐时，Way 先给少量有差异的旅行方向或具体体验。用户可以查看详情、多选、取消、换一批，也可以继续用文字补充偏好。

已选内容会保留。用户可以选好后生成路线，也可以直接说“你帮我安排”，不必逐一勾选。

### 4.3 阅读并调整当前行程

计划生成后，用户先看全程路线和每天的安排，再进入某一天阅读路书。地图上的地点、当天的活动和对应的出行提示应能相互对应，不需要用户从聊天记录中重新拼出攻略；对话入口用于继续提问或修改。

例如，用户说“去掉一个城市，多留两天在大阪”，Way 应调整城市顺序、住宿和交通，而不只改写一段说明。用户可以查看主要变化，或撤销最近一次修改。

## 5. 功能需求

本节列出本版需要达到的功能要求，具体通过条件见第 7 节；功能要求不代表当前已经完成验收。

### 5.1 旅行信息与条件确认

了解出发地、目的地或旅行方向、日期与总天数、同行情况、兴趣、预算、可以接受的交通方式，以及已有预订。已知信息不重复询问，尚未决定的内容允许暂时空缺。

区分明确要求与一般偏好：例如“不自驾”“已订好某天的返程航班”必须遵守，“尽量少换酒店”则可以在说明理由后提出其他方案。信息不全时，可以先提供不受影响的建议；需要暂定条件时应明确说明，不能当作用户已经确认。

总天数包含出发和返回。用户纠正条件后，后续推荐使用新条件，并保留仍然适用的选择。

### 5.2 目的地发现与体验推荐

未确定目的地时，结合假期、出发地、兴趣、季节和预算，推荐几个不同的旅行方向，说明适合的原因、主要体验、路上耗时及需要注意的条件。已确定目的地时，推荐当地的地区、地点和活动。

每项推荐至少说明：

- 去哪里，主要能看到什么或做什么。
- 为什么适合用户本次表达的兴趣或要求。
- 建议预留多少时间，有什么交通、开放或预约条件。
- 可以进一步了解的详情来源。

“换一批”要提供新的选择，不能只是换个说法重复推荐。不同批次的勾选累积在同一清单中，支持逐项移除。没有勾选不等于明确拒绝；用户明确排除的内容不得重新加入。

资料不足时可以减少推荐数量，或说明还缺什么依据，不为凑数编造地点和体验。

### 5.3 路线与每日路书

先展示全程路线：经过哪些地方、分别停留多久、乘坐什么交通工具。每日安排写清地点顺序、游玩和路上所需的时间、休息及住宿区域。

每日路书围绕这一天的实际安排提供内容：

- **当天怎么玩**：主要体验、建议游览顺序、停留时长与安排理由，不只重复地点名称。
- **怎么衔接**：从住宿地到首个活动、地点之间和当天结束后的交通方式，标明需要核实的班次或接送条件。
- **提前准备什么**：适用于当天活动的预约、装备、体力与开放条件；没有特殊要求时不强行填充。
- **遇到变化怎么办**：对受天气、开放条件或体力影响较大的活动，提供可选的替代安排，并说明何时适用。

玩法、参考来源和待确认事项放在对应日期、地点下，方便用户查阅。路书应写具体的出行信息，不能只有通用的目的地介绍。

安排时遵循以下规则：

- 先安排固定交通、住宿和必去体验，再补充其他活动。
- 将去程、返程、接送和长距离转场计入总天数，避免把抵达日当作完整游玩日。
- 用户选中的体验应被安排；无法兼顾时指出具体冲突，并给出换日、替换、删减或延长行程的办法。
- 为完善行程而补充的活动标为建议，允许用户替换。
- 避免不必要的折返，不为排满日程而重复安排活动，保留适当休息时间。
- 对重要取舍说明理由，例如为什么在返程前一晚回到出发城市、为什么不建议当天往返某个远距离地点。

日期未定时用“第 1 天、第 2 天”安排行程，并注明受季节或日期影响的活动。航班、车次未确定时先预留交通时间，不编造具体班次，也不写成已经预订。

### 5.4 住宿、交通与预算参考

住宿建议以区域为主，说明住在哪里方便当天游玩和第二天出发、哪天需要换住宿，不以挑选具体酒店为重点。住宿晚数应与抵达、离开日期一致，在飞机或列车上过夜不计入酒店住宿。

交通可以组合飞机、铁路、公交、包车、步行等方式。用户愿意自驾不代表必须全程租车；不自驾时，要检查核心体验是否有可接受的其他到达方式。

预算作为推荐和取舍的条件。有依据时提供粗略费用范围，并说明人数、天数及包含项目；主要支出缺少依据时，不拼出看似精确的总价。完整费用汇总与逐项比价不在本版范围内。

### 5.5 行程修改与结果保存

支持修改单日活动、删除或增加地点、调整天数和节奏，以及更新交通或住宿条件。修改后检查受影响的日期、交通和住宿，同步更新路书中的玩法、预约提醒和备选安排，保留其他有效内容，并说明主要变化。被删除活动的专属提醒不应残留在当前计划中。

一般修改直接更新，并提供撤销。如果修改与已有预订或明确要求冲突，先说明冲突并请用户选择，不能擅自改掉固定安排。

生成或修改期间，旧路线仍可查看。取消、失败或结果不完整时保留原版本，明确提示尚未更新，并允许重试。旅行信息、选择和当前路线应在刷新后恢复；切换旅行不应混用内容。当前保存范围为同一浏览器，不承诺跨设备同步。

### 5.6 信息来源与行前事项

旅行介绍和体验资料用于发现玩法；开放、预约和交通等关键条件优先查询相应官方或运营方信息。来源应紧邻相关内容，用户可以打开查看；一个链接只能支持它实际包含的信息。

提醒要写清“什么情况会影响哪项安排，以及可以怎么办”。例如，户外活动可能受天气影响，应提供可替换的活动，而不只是提示“注意天气”。

区分普通待确认事项和可能导致行程无法完成的问题，不把所有不确定性都标成高风险。日期未定时给季节性建议，不编造某一天的天气；跨国时差等信息需核对。修改行程后同步更新相关提醒。

### 5.7 地图与导出

地图显示地区、主要地点及游玩顺序，日期编号对应当天路线与路书，地图、日程和路书中的地点名称及日期保持一致。采用固定的 2D 区域视图，地名和编号在桌面及手机上都应可读、可点；不承担道路导航功能。无法可靠定位的地点应说明，不显示误导性的精确坐标。

用户可将当前计划导出为 PDF，包含全程路线、地图、每日路书、住宿建议和行前事项。导出内容与当前保存的版本一致，未确认的信息仍保留待确认标记。

### 5.8 处理速度与等待体验

不必对所有请求都进行长时间分析。答案已在当前行程中的问题直接回答；解释、整理和简单局部修改优先快速完成。新路线、复杂调整及重要信息核查需要更充分的分析。

快速处理也可以联网查询。是否搜索取决于现有资料够不够，不能把“快速”等同于“不联网”。结果不完整或不符合要求时，继续检查和处理。等待时显示正在进行的步骤和已用时间，允许取消，不展示虚构进度。

## 6. 本版范围与优先级

| 优先级 | 必须交付的能力 |
| --- | --- |
| P0 | 从模糊想法或已有条件开始，确认影响规划的关键信息 |
| P0 | 提供有理由、有差异的旅行方向和体验，保留用户选择 |
| P0 | 生成相互对应的路线与每日路书，涵盖往返、交通、住宿区域、玩法及关键准备事项 |
| P0 | 修改时一起更新路线与路书；修改失败时保留原计划 |
| P1 | 地图查看、来源展开、进度提示、旅行切换、恢复、撤销及 PDF 导出 |
| P2 | 完整费用汇总、只读分享链接与历史版本比较 |

P0 是完成一份旅行计划所必需的能力；P1 让用户更容易查看、保存和带走计划；P2 可在后续版本中补充。

当前公开体验范围为 Showcase，提供大阪与鸟取、新西兰南岛和大理三个旅行案例。用户在案例提供的地点与体验中选择，并通过预设对话选项体验路线生成和修改；案例资料与安排应标明为示例。

Live 根据用户自由输入的旅行条件生成建议，并在需要时联网查询资料，目前仅用于内部验证，尚未向公众开放。Live 内部验收通过不等于向公众开放。

本版不处理订票、支付、改签或订单取消，也不建设旅行社区、多人投票和酒店商品比较。计划建议与真实订单始终分开。

## 7. 验收标准

产品质量通过推荐是否合适、路线与路书是否一致、修改是否落实来衡量。公开 Showcase 与内部 Live 分别验收；以下比例是待达到的目标，不代表已有验收结果。

每个规划或修改样本都须检查明确要求、固定预订和路线与路书的一致性。违反这些条件的结果不得交付或保存为当前计划；首次规划失败时提示未生成，修改失败时保留原计划，并允许重试。85% 的首版通过率和 95% 的修改落实率衡量任务完成情况，不能用来容许错误计划交付。

| 项目 | 目标 | 检查要求 |
| --- | --- | --- |
| 首版规划 | 30–50 个全新 Live 规划请求中，至少 85% 生成合格计划 | 覆盖未定目的地、已定目的地及已有固定安排；推荐理由符合需求，总天数正确，交通衔接合理，主要事实有依据或标明待确认；失败、超时和未生成均计入分母 |
| 路线与路书对应 | 公开 Showcase 的 3 个案例及内部 Live 验收中实际交付的计划，逐日一致性通过率均为 100% | 日期、地点、交通及住宿相互对应，每天能查到玩法与必要准备事项；修改后无已删除活动的专属提醒；无特殊准备要求时允许简写，不以篇幅作为合格依据 |
| 个性化推荐 | 至少 5 组同目的地、不同需求的对比检查全部通过 | 差异应体现在地点、活动或交通安排中；只改推荐文案不算通过 |
| 修改落实 | 至少 20 个有效修改请求中，落实率达到 95% | 有效请求指确实需要改动且不与固定条件冲突的请求；路线、路书及相关提醒同步更新，其他固定条件保留才算成功；失败、超时和未更新均计入分母，冲突请求另验确认流程 |
| 要求与选择保留 | 公开 Showcase 与内部 Live 实际交付的计划，明确要求遵守率均为 100%；已选体验安排或解释取舍的比例为 100% | 必去、排除项、交通及固定住宿均符合当前已确认条件；跨批选择不遗漏、不重复，冲突须说明并取得用户选择后再改动固定安排 |
| 简单请求速度 | 无需新资料的简单请求，中位完成时间不超过 40 秒 | 同时报告正确完成比例、失败及超时数量；失败不计作完成，升级后的完整耗时计入统计，不能只统计较快的成功样本 |
| 案例操作 | 3 个公开案例在桌面和 375px 手机宽度的全部规定流程均通过 | 实际完成跨批选择、生成、修改、地图查看、撤销、刷新恢复和导出；恢复后的选择与计划保持一致，PDF 与当前计划一致 |
